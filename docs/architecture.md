# Architecture

The project separates ingestion, retrieval, generation, API delivery and
evaluation so each layer can be tested independently.

```text
Incidents / Runbooks / FAQ
          |
          v
 Loader -> Chunker -> Embeddings -> FAISS
                               |
User -> FastAPI -> Retriever --+
          |          |
          |          v
          |     Top-K chunks
          |          |
          v          v
     RAG service -> Context builder -> Generator
          |                              |
          +-------- Answer + sources <---+
          |
          +---- structured timing data

Evaluation dataset -> Retriever -> Hit Rate@K / Recall@K / MRR / failures
```

## Design choices

- FAISS keeps the portfolio project local and reproducible.
- Embedding and generation providers are configurable rather than spread
  throughout application code.
- A deterministic context generator lets tests and demos run without paid API
  calls; OpenAI and local Ollama generation are optional.
- Source citations are built from retrieval metadata, not generated by a model.
- The project uses synthetic support data and does not claim connection to a
  real enterprise incident system.
