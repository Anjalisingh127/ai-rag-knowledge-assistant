# Architecture

The project separates ingestion, retrieval, generation, API delivery and evaluation so each layer can be tested independently. It supports two validated execution paths: the local/Docker path and the public Streamlit Community Cloud path.

## Local and Docker execution

```text
Incidents / Runbooks / FAQ
          |
          v
 Loader -> Chunker -> MiniLM -> FAISS
                               |
User -> Streamlit -> FastAPI -> Retriever
                         |         |
                         |         v
                         |    Top-K chunks
                         |         |
                         v         v
                    RAG service -> Context builder -> Generator
                         |                              |
                         +-------- Answer + sources <---+
                         |
                         +---- structured timing data
```

In Docker, FastAPI and Streamlit run as separate services. Docker Compose provides internal service networking, the API exposes a healthcheck, and the UI waits until the API is healthy before starting.

## Public Streamlit execution

The public deployment avoids a separately hosted API so the portfolio demo can run on Streamlit Community Cloud without requiring a second paid or separately managed backend service.

```text
Incidents / Runbooks / FAQ
          |
          v
 Loader -> Chunker -> MiniLM -> FAISS
                               |
Public user -> Streamlit UI -> RAG service
                                |
                                v
                           Retriever
                                |
                                v
                           Top-K chunks
                                |
                                v
                         Grounding check
                          /           \
                         v             v
               Context generator    Abstain
                         |             |
                         +------ Answer + sources
```

The Streamlit cloud entrypoint builds the local FAISS index when it is not already available, loads the same RAG service used by the API path, and caches the initialized service for reuse within the running Streamlit process.

## Evaluation path

The evaluation dataset is intentionally isolated from the searchable knowledge base.

```text
Evaluation dataset
      |
      v
Evaluation runner
      |
      +--> deterministic hash baseline
      |
      +--> MiniLM semantic retrieval
      |
      v
Hit Rate@K / Recall@K / MRR / failure analysis
```

## Design choices

- FAISS keeps the portfolio project local, lightweight and reproducible.
- Embedding and generation providers are configurable rather than spread throughout application code.
- A deterministic context generator lets tests and demos run without paid API calls; OpenAI and local Ollama generation are optional.
- Source references are built from retrieval metadata, not generated by a model.
- The local/Docker path preserves API/UI separation, while the public Streamlit path runs the same RAG service in-process to avoid requiring a second hosted backend.
- Evaluation data is excluded from ingestion to avoid benchmark leakage.
- The project uses synthetic support data and does not claim connection to a real enterprise incident system.
